## Check machines in Manager

Select a machine on **Machines** and choose **Refresh status**. Check its
**Network**, **Service** and **Ready** fields. Status is an observation; refresh
it before deciding that a machine is healthy or needs maintenance.

The wallet shows the connected node's block height. A height that stops advancing,
unreachable machine or storage warning needs investigation. An unavailable
status is unknown, not a height of zero. Manager does not yet show archive
completeness or a comparison of all machines' block hashes.

Use **Maintenance** for a reviewed node restart and its saved request. Restart
one machine at a time and check the outcome. If it is the only eligible producer,
block production pauses until it is back and ready.

If Manager shows **Stopped: insufficient RAM**, chain processing has stopped
deliberately while management remains available. Increase the machine or VM's RAM,
or free memory used by other workloads, then open **Maintenance** and review
**Start node**. Authenticate on the phone and use **Check saved start** to observe
the original result. A start uses the existing signed network, history and FILEs;
it cannot create a replacement network or repair corrupted history. Readiness
and block height remain unavailable while the chain daemon is stopped.

If memory is still insufficient, the node refuses startup. A failed start may be
dismissed before a new deliberate request after fixing the cause; an unknown or
unresolved start retains its original request for checking.

## Open Riadchain

In the **Riadchain** app's **Settings**, select your account and network. A setup
performed through this wallet retains its owner accounts and connection
credentials. Unlock the selected connection when asked.

Use the wallet for [reviewed transfers](/apps/native-wallet/#receive-and-send)
and applications configured on your network. An app installation does not
automatically deploy its contracts. Follow its own setup instructions for
[names](/apps/names/), [messages](/apps/chat/) or [home applications](/apps/smart-home/).

Funding another machine's **owner** account can make its already authorized
signer eligible to produce blocks. Verify the owner address and network first.
Keep enough available funds on the existing producer: initial setup funds it
with the minimum 1 RDC, and transfers and fees reduce that balance. Claim accrued
rewards before moving funds; unclaimed rewards do not count toward eligibility.
Manager does not allocate coins or change that eligibility.

Wallet connections also need a reachable node address. Distribution wallet
builds require HTTPS; the local testing build can use private HTTP. Your installer
must supply a connection that works with your app build. Discovery in Manager
does not automatically repair the wallet or node peer addresses.

## Keep your backups

- **Paper phrases and account indexes** recover owner accounts if you lose the
  phone. Never share them with support or enter them into Manager. They do not
  automatically restore management enrollment or node connection credentials.
- **Network records** identify the intended machines and signed network. Keep
  the original request and signed setup with your purchase information.
- **History and file backups** recover stored data. A recovery phrase cannot
  recreate missing photos, documents or chain history.

A mirror helps with a failed drive inside one machine. A separate replica helps
with a lost machine; a copy at another location helps with a site outage. None
of these alone proves that every committed file has been copied. Verified
[history and FILE backups](/node/backup-recovery/) currently need the operator
tools; Manager does not yet provide archive backup or restore.

The current multi-machine setup needs an archive peer to acknowledge new FILE
publications. Another eligible producer alone does not guarantee uninterrupted
file writes while every other archive peer is unavailable.
