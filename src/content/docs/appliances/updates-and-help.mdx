## Install a node update

1. Obtain a signed **`.riadupdate`** bundle from the trusted release channel
   supplied with your installation. Manager has no built-in download catalogue yet.
2. Open Manager's **Updates**, select the intended paired machine and choose
   **Import update**. **Local preview · not verified** shows the file's claims.
3. Choose **Transfer and verify**. Wait for **Publisher verified by machine**
   before reviewing the actual package.
4. Choose **Review installation**, confirm the machine and version, then
   authorize installation on the phone.
5. Use **Check saved install** until the original job, expected package and healthy
   original network confirm completion. Choose **Dismiss completed update** after
   verifying success. Repeat for each intended machine.

The phone needs a reachable local or private route to the machine. It can carry
the downloaded bundle onto an internet-isolated LAN; the machine does not need
public internet for this transfer. This is not a physically disconnected update.

Linux, Manager and the wallet use their own update procedures. A node package
update does not change the [network's consensus rules](/protocol/upgrades/).

## When an operation is uncertain

If pairing, preparation, start, restart or installation loses its reply, keep the
original saved request. Use the corresponding **Check** action in Manager to
reconcile what the machine recorded.

“Unknown” or “unresolved” does not mean nothing happened. Returning to the app
does not automatically repeat the operation. Where an explicit retry is offered,
it uses that original request; do not clear app data, generate fresh keys or
submit a replacement network.

If transfer is interrupted, retain the imported file and select **Resume
transfer**. **Transfer and verify** remains the action while the machine has
confirmed zero bytes. If installation is uncertain, keep the original operation
reference and use **Check saved install** before making another request.

## Prepare a signed bundle

Release operators and agents need access to the implementation checkout, a
matching Debian builder and the target's trusted publisher public key. Confirm
the installed package, architecture and network format. Choose a strictly newer
package revision and a release sequence above the appliance's accepted sequence.
Build the exact reviewed source with the pinned toolchain. Qualify that package
against a disposable node's existing signed history, checking the original
block anchor, normal startup and known FILE bytes.

With `NODE_DEB`, `PUBLISHER_KEY`, `RELEASE_SEQUENCE` and `BUNDLE` set to the
reviewed values, run the implementation's builder from the repository root:

```sh
python3 scripts/build-appliance-update.py \
  --node-deb "$NODE_DEB" --signing-key "$PUBLISHER_KEY" \
  --sequence "$RELEASE_SEQUENCE" --genesis-format ml-dsa-65 \
  --protocol-id 3 --output "$BUNDLE"
```

Use the qualified binary's actual IDs from `riadchain-cli protocol capabilities`.
The example uses the current private release's ID. The publisher signs locally
with the key already trusted by the appliance. If it is encrypted, the operator
enters its passphrase privately at the local Minisign prompt.

Verify the bundle using the appliance verifier and trusted public key. Set
`STAGING` to an empty protected directory and choose the exact target architecture:

```sh
riadchain-update verify --bundle "$BUNDLE" \
  --publisher-key /etc/riadchain-manager/publisher.pub \
  --architecture amd64 --extract "$STAGING"
cmp -- "$NODE_DEB" "$STAGING/node.deb"
sha256sum "$BUNDLE"
```

Provide the operator the bundle path, expected revision and SHA-256. The package
build, bundle signature and successful live installation are separate results.

## Common checks

| What you see | What to check |
| --- | --- |
| No machine found | Power, Ethernet, phone Wi-Fi and local-network access. Try its known private address; discovery is optional. |
| Machine unreachable | The private route and saved address. An address change must not replace its trusted identity. |
| Stopped: insufficient RAM | Increase available machine/VM RAM or its service limit, then review Start node in Maintenance. The management service can remain available while the chain daemon is stopped. |
| Stopped: service failure | Have the operator inspect the node logs before attempting Start node; starting does not repair corrupted history or replace missing FILE bytes. |
| Certificate could not be verified | Machine identity and both devices' clocks. Keep verification enabled. |
| Status unavailable or network unknown | Refresh on the machine's private network. If it persists, ask the operator to check the paired address and both services. Keep the imported bundle and pairing. |
| Updates unavailable or publisher rejected | Ask the operator to check the provisioned publisher public key and exact bundle. |
| Preparation failed | Read its stated reason and check all original outcomes. A failed job differs from an uncertain or partially installed job. |

## What the current repair controls do

The wallet's **Repair setup file** recreates malformed encrypted setup files
using the same keys and signed network. It is not general machine recovery.
Manager's **Import corrected setup** is available only when every original
preparation failed, nothing was started and the machines remain unconfigured.
It retains the rejected attempts before saving new preparation requests.

These controls cannot fix a running network, recover missing owner keys or
restore archive data. For a valid encrypted file rejected by a machine, simply
exporting the unchanged file again does not fix the underlying problem.

## Ask for help

Use the support contact supplied with your order. Include the app version,
machine identity, displayed error and saved request reference. Screenshots of
public status and error messages help. Never send passwords, recovery phrases,
access tokens or a screenshot of revealed keys.

Release apps protect private screens from screenshots. The images in this guide
were captured from disposable debug installations without customer secrets.
