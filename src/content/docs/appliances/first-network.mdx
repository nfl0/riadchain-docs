---
title: Create your network
description: Set up a new private network using Manager and the Riadchain wallet, keeping the same saved files throughout.
---

Start after [pairing your machines](/appliances/connect-machines/). This creates
a **new** network on prepared, unconfigured machines. Joining an existing network
or restoring its archive through Manager is not available yet. Physical Debian
machines and [Proxmox VMs](/node/proxmox/) use the same setup workflow.

Advanced users can create a one-machine network through the
[workstation CLI clients](/node/cli-setup/) instead. Choose CLI or phone for the
machine's single controller; independent simultaneous enrollment is unavailable.

## 1. Choose the machines in Manager

On **Machines**, find **Set up a network** and choose **Choose machines**.
Select only the machines intended for this network, then choose **Create request**.
The current setup uses the first machine in the request as the funded block
producer; the others start as replicas. You will review that identity in the wallet.
One prepared machine can start a network. Its signed setup uses zero required
FILE peer acknowledgements, so local file publication works without another node;
local CID/size verification still applies. This policy is fixed in genesis and
adding a replica later does not change it. With multiple prepared machines, setup
requires one peer acknowledgement.

Choose **Save setup request** and save the `.riadrequest` file somewhere you can
find again on your phone. Manager records the latest protocol supported by all
selected machines at block 1. Machines with different starting rules need matching
software before setup. Use Android's file picker for each handoff below; there
is no automatic app-to-app transfer yet.

## 2. Back up the keys in Riadchain

Open the **Riadchain** app, then **Settings → Set up appliances → Import setup
request**. Select the saved `.riadrequest` and check the machines and starting
protocol. Genesis is block 0; the recorded starting protocol applies at block 1. Check
that the machine labelled **Validator** is the intended first producer before
choosing **Unlock or create network keys**. If the list is wrong, stop and check
the selection with your installer before creating keys or signing.

Reveal and write down all three phrases, using the app's exact labels:
**Validator**, **Recovery**, and **Replacement validator**. If there are multiple
replicas, also record their account indexes shown by the app. Keep these backups
offline and private, then choose **I backed up all three phrases**.

These labels identify key groups, not different machine models. The replacement
owner's key remains off your operating machines.

## 3. Review the network definition

Follow the handoff in order:

| In this app | Choose | Open the saved file in |
| --- | --- | --- |
| Riadchain | **Export network plan** (`.riadplan`) | Manager: **Import network plan** |
| Manager | **Save prepared definition** (`.riadgenesis`) | Riadchain: **Import prepared genesis** |
| Riadchain | Review the matching definition, then **Sign and seal appliance keys** and **Export sealed setup** (`.riadsetup`) | Manager: **Import sealed setup** |

The wallet checks that the prepared network matches your original request before
signing. Your phrases and owner keys stay in the wallet. The sealed file contains
public network information and encrypted machine credentials.

## 4. Prepare, then start

In Manager, review **Prepare machines** and authorize it on your phone. Choose
**Check setup outcomes** until every machine reports **Prepare: succeeded**.
Then review **Start network** and authorize it.

Check outcomes again until all original start jobs report **Start: succeeded**.
Refresh each machine and confirm its expected **Network**, active **Service**
and **Ready** status. The wallet shows block height; blocks normally arrive every
ten seconds. Manager does not currently display block hashes or archive coverage.

If a result is unknown or unresolved, keep the saved request and [check its
outcome](/appliances/updates-and-help/#when-an-operation-is-uncertain). Do not
create another network or new recovery phrases to retry it.

## 5. Keep the setup record

Keep the request, signed setup, account indexes and paper phrase backups.
**Close completed setup** in Manager closes the workflow without stopping nodes.
Archiving the signed wallet setup retains its original keys and file for later
reimport; it does not erase a running network.

Additional machines can become eligible producers when their owner accounts are
funded through the wallet. The current setup screen does not offer a multiple
producer allocation selector. Your shop preferences do not change network rules
or move funds automatically.
