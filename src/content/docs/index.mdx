Riadchain is a **private, permissioned blockchain** for homes and companies.
Each deployment has its own network identity, trusted participants and applications.
A Rust node provides succession-based consensus, the Charlie contract runtime,
and native FILE storage. The project is in active development; these guides use
networks you operate and verified contract addresses, rather than a shared public mainnet.

## How the network fits together

Wallets and applications submit signed transactions to a Rust producer. Followers
verify the same signed history, and each node keeps its own FILE archive. Canonical
blocks record file references; verified transfers replicate the corresponding bytes.

## Store files with your node

FILE transactions commit a content identifier and metadata to the chain. Your
node stores the corresponding bytes in its local archive and can serve and
replicate them. Keeping canonical history and keeping those bytes available are
different responsibilities. Learn how to [operate the FILE archive](/node/file-archive/)
and [upload files through the SDK](/developers/files/).

## Give your machines readable names

[RiadNames](/apps/names/) maps names such as `robot.kitchen` and `agent.inventory`
to owner-controlled profiles and destinations on your home or company chain.
Browse your namespace, register an entity, and review changes through Keychain.
